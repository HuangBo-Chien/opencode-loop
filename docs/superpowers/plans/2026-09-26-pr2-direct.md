# PR2 Direct Execution Implementation Plan

> **For agentic workers:** Use subagent-driven-development for implementation and independent review. Keep implementation edits sequential; preserve existing PR1 behavior.

**Goal:** A bounded ordinary task uses one worker and runner-owned mechanical acceptance, with Graph available on demand.

**Architecture:** Reuse existing implementer dispatch bindings, persistence transactions and settlement. Store a distinct Direct contract and acceptance artifact; do not fabricate planner or critic output. Keep filesystem inventory and command execution in small dedicated modules.

**Tech Stack:** Node.js ES modules, node:test, the installed @opencode-ai/plugin tool API.

## Task 1: Workspace evidence and bounded command execution

Files: new `src/direct-workspace.mjs`, `src/direct-check.mjs`, `test/direct-evidence.test.mjs`.

- [x] Write failing tests for complete bounded workspace inventory, changed/deleted/unreported files, symlink escape rejection, dirty baseline preservation, real command success/failure, timeout and output bounds.
- [x] Run `node --test test/direct-evidence.test.mjs` and verify expected failures.
- [x] Implement `captureWorkspace(worktree, {stateDirectory})` returning a stable map of relative paths to hashes, with bounded size/count and no following symlinks outside the workspace. Exclude only documented infrastructure paths; do not ignore source changes merely because Git ignores them.
- [x] Implement `runDirectCommand({command,cwd,timeoutMs,signal})` returning bounded output and actual exit status. Hide Windows helper windows, kill the process tree on timeout/cancellation where supported, and report uncertain termination rather than fabricating success.
- [x] Verify with real temporary files and subprocesses. Commands must not run before their permission is obtained by the caller.

Tests: `test/direct.test.mjs` and existing affected tests.

- [x] Write failing tests for `executionStrategy` default auto and graph rollback, root-only versioned contract creation, a single implementer without plan/review/verify nodes, and Graph compatibility.
- [x] Add `graph_direct_start` to validate and persist requirement, acceptance, scopes, deliverables, command ids/commands/cwd/timeouts and rationale before admitting writes. Persist strategy on new runs; missing strategy remains legacy Graph on reload.
- [x] Add `graph_direct_check({checkId})`: authenticate current worker/attempt, resolve the command exclusively from the durable contract, ask permission through tool context, persist pending operation, execute, capture before/after workspace inventories, and commit evidence with run/session/dispatch/attempt/contract identity. Handle abort, timeout, failure and persistence fencing separately.
- [x] Require Direct submission to match all named current successful checks and workspace revision, declare actual touched/deleted files, preserve baseline dirty files and satisfy deliverables and scope. Reject forged model `checksRun`, stale evidence and unresolved work. Publish runner-owned acceptance only on success.
- [x] Keep local repair in the current worker, bound check/retry rounds across dispatch reuse, and retain PR1 completion settlement. Late tools or outstanding checks cannot turn an incomplete task into success.
- [x] Bound pre-contract investigation. Add root-only escalation/revision at a settled boundary, preserve evidence and attempt budgets, and enforce normal Graph gates after escalation.
- [x] Update prompts and permissions to prefer Direct for mechanically verifiable bounded tasks and Graph for independent semantic review/decomposition. Reuse the existing implementer role.
- [x] Run `node --test test/direct.test.mjs test/direct-evidence.test.mjs` plus affected regression files until passing.
